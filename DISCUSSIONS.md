# Discussions

Discussions hold the conversations that are not yet work: questions, ideas being
shaped, things people have built around visor. Issues hold work someone has
agreed to do. Both are open, and the difference is whether a change has been
committed to.

## Which category

| Category | What belongs there |
|---|---|
| Announcements | Release notes and changes that affect how you use visor. Maintainers post here; replies belong in General. |
| Q&A | A question about visor: setup, editor wiring, an error you cannot explain. |
| Ideas | Something visor should do, before anyone has shaped it into a plan. |
| Show and tell | Editor configurations, scripts and tools built around visor. |
| General | Everything that does not fit the categories above. |
| Polls | A vote where the options are the whole point. |

## Rules

1. Search the issues, the discussions and `ROADMAP.md` before posting. The
   out-of-scope list in the roadmap is the most common answer.
2. One topic per thread. A follow-up question with a different answer belongs in
   a new thread, where the next person searching can find it.
3. Confirmed bugs go to the issue tracker, not here. If you are not sure whether
   something is a bug, ask in Q&A and a maintainer will move it.
4. Security problems go through `SECURITY.md`. Never post one in a discussion,
   including in a private one.
5. Code goes in fenced blocks with the language tag. Logs get trimmed to the
   lines that matter, with the rest attached rather than pasted.
6. In Q&A, mark the reply that solved it. It is the only signal the next person
   searching gets, and an unmarked answer is a thread nobody can use.
7. Behaviour is governed by `CODE_OF_CONDUCT.md`, which also has the reporting
   route. That applies here as much as in the tracker.
8. English, since the tracker, the docs and the code are in English.

## What maintainers do to a thread

Moving a thread to another category, closing a duplicate, or converting an idea
into an issue is housekeeping, not a verdict on the question. An idea that is
agreed becomes an issue, because an issue is where work gets tracked; an idea
that is not taken up stays open until the roadmap explains why it is not.

## What this is not

Discussions are not a support contract and not a release channel. Announcements
arrive when there is something to announce, and the tracker is where a decision
shows up.
